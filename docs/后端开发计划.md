# 后端开发计划

## 一、 项目基础架构搭建阶段（第一阶段）
**目标**：搭建完整的 FastAPI 后端项目基础架构，含目录结构、依赖配置、核心接口定义。

### 1. 目录结构设计
```text
backend/
├── app/
│   ├── __init__.py
│   ├── main.py                 # FastAPI 应用入口
│   ├── api/                    # 路由层
│   │   ├── __init__.py
│   │   ├── deps.py             # 依赖注入 (如获取数据库实例)
│   │   └── endpoints/          # 接口路由
│   │       ├── document.py     # 文档管理及文件上传
│   │       ├── ocr.py          # OCR 识别状态轮询相关
│   │       ├── model.py        # 模型配置管理
│   │       └── chat.py         # 问答交互
│   ├── core/                   # 核心配置
│   │   ├── __init__.py
│   │   └── config.py           # 环境变量与配置管理
│   ├── db/                     # 数据库层
│   │   ├── __init__.py
│   │   └── supabase.py         # Supabase 客户端初始化
│   ├── schemas/                # Pydantic 数据验证模型
│   │   ├── __init__.py
│   │   ├── document.py
│   │   ├── model.py
│   │   └── chat.py
│   ├── services/               # 核心业务逻辑
│   │   ├── __init__.py
│   │   ├── ocr_service.py      # 对接 PaddleOCR-VL 1.5
│   │   └── llm_service.py      # OpenAPI 格式 LLM 调用
├── tests/                      # 单元测试代码
├── requirements.txt            # 项目依赖
└── .env.example                # 环境变量示例
```

### 2. 核心依赖清单 (`requirements.txt`)
- `fastapi`: 核心框架
- `uvicorn`: ASGI 服务器
- `supabase`: Supabase 官方 Python SDK
- `pydantic`, `pydantic-settings`: 数据验证与环境配置管理
- `httpx`: 异步 HTTP 客户端（用于调用 PaddleOCR 和 LLM API）
- `python-multipart`: 支持文件上传
- `pytest`, `pytest-asyncio`: 单元测试

### 3. 核心接口定义规划
- **文档模块 (`/api/document`)**
  - `POST /upload`: 接收文件并提交 PaddleOCR 任务
  - `GET /list`: 获取知识库文档列表
  - `DELETE /{doc_id}`: 删除指定的文档
  - `PUT /{doc_id}`: 编辑文档的 OCR 内容
- **OCR 状态模块 (`/api/ocr`)**
  - `GET /status/{job_id}`: 轮询 PaddleOCR 任务状态并处理完成的数据同步
- **模型配置模块 (`/api/model`)**
  - `GET /list`: 获取模型配置列表
  - `POST /add`: 新建模型配置
  - `PUT /{model_id}`: 修改模型配置
  - `DELETE /{model_id}`: 删除模型配置
- **问答交互模块 (`/api/chat`)**
  - `POST /ask`: 提交提问并获取大模型回复
  - `POST /clear`: 清空历史对话

## 二、 渐进式模块开发阶段（第二阶段）

按照以下顺序逐一开发，每个模块完成后独立编写对应的单元测试并验证，并更新 `开发进度.md`：

### 模块 A：基础架构与数据库连接
1. 创建目录结构，配置 `core/config.py`。
2. 接入 Supabase 客户端 (`db/supabase.py`)。
3. 提供基础连通性测试。

### 模块 B：模型配置管理模块
1. 数据库建表要求确认（在 Supabase 构建表结构：`models`表）。
2. 实现 `schema` 结构。
3. 实现 CRUD 接口，涉及 API KEY 的加解密存储或隐藏处理。
4. 编写并通关单元测试。

### 模块 C：文件上传与 OCR 服务集成
1. 数据库建表要求确认（在 Supabase 构建表结构：`documents`表）。
2. 实现 `services/ocr_service.py` 提交异步任务。
3. 实现 `/upload` 上传接口与文件校验。
4. 实现 `/status/{job_id}` 轮询接口解析 JSONL 结果并入库。
5. 编写并通关单元测试。

### 模块 D：文档管理模块
1. 实现列表查询 (`/list`)、删除 (`/{doc_id}`) 和内容编辑更新 (`/{doc_id}`) 接口。
2. 编写并通关单元测试。

### 模块 E：问答交互引擎与 LLM 对接
1. 数据库建表要求确认（在 Supabase 构建表结构：`chats`表）。
2. 实现 `services/llm_service.py`。
3. 实现根据模型配置、提示词和选中文件构建 prompt 发起提问。
4. 实现历史记录存储与清空功能。
5. 编写并通关单元测试。
