# 基于文件的问答系统开发说明书

## 一、文档概述

### 1.1 开发目的

本文档用于明确基于文件的问答系统的全流程开发需求，包含UI设计、后端接口开发、OCR接口集成（PaddleOCR-VL 1.5）、前后端交互、数据库配置及Vercel部署等核心内容，为开发人员提供清晰的开发指引，确保系统功能完整、交互流畅、接口调用正常，实现多格式文件问答、知识库管理、模型配置三大核心功能，并成功部署上线。

### 1.2 系统核心定位

本系统是一款支持多格式文件（Word/TXT/PDF【含扫描件、电子版】、图片）的问答工具，无需RAG技术，通过PaddleOCR-VL 1.5完成文件OCR识别，再由LLM通读识别后的文档全文响应用户问题。核心功能包含问答交互、知识库管理、模型配置，面向有文件问答需求的用户，追求操作简单、功能明确、交互流畅、识别精准，基于指定技术栈（NEXT.js+FastAPI+Supabase）开发，最终部署于Vercel平台。

### 1.3 开发范围

本次开发覆盖系统全部模块，具体包括：

1.  UI层：基于NEXT.js开发问答交互页面、知识库管理页面、模型配置页面（含布局、组件、交互逻辑）；

2.  后端层：基于FastAPI开发接口、集成Supabase数据库（存储文档信息、模型配置、对话历史）、集成PaddleOCR-VL 1.5接口、实现LLM模型调用；

3.  前后端交互：NEXT.js前端与FastAPI后端接口联动，确保数据同步、操作响应正常；

4.  数据库：基于Supabase配置数据表，实现数据的存储、查询、更新、删除；

5.  部署：将前后端项目打包，部署至Vercel平台，确保系统可正常访问；

6.  核心功能：文件上传与OCR识别、文档管理（删除、编辑）、模型配置（新建/编辑/删除）、问答交互（提问、提示词设置、历史清空）。

## 二、整体开发规范（通用要求）

### 2.1 技术栈指定（强制要求）

- 前端：NEXT.js（优先使用App Router），搭配Tailwind CSS/Element Plus组件库，确保UI美观、交互流畅，适配常见电脑屏幕尺寸，兼顾SSR渲染优势，提升页面加载速度；

- 后端：FastAPI（Python），利用其高性能、自动生成接口文档、易于集成第三方API的优势，快速开发后端接口；

- 数据库：Supabase（基于PostgreSQL），用于存储文档信息、模型配置参数、对话历史，后续补充数据库连接、密钥等相关参数；

- 第三方接口：集成PaddleOCR-VL 1.5（OCR识别）、OpenAI兼容模型（LLM问答）；

- 部署平台：Vercel，用于部署前后端项目（NEXT.js前端可直接部署，FastAPI后端可通过Vercel的Serverless Functions部署）。

### 2.2 接口规范


- 状态码规范：200（成功）、400（请求参数错误）、401（未授权）、404（资源不存在）、500（服务器内部错误）；

- 异常处理：所有FastAPI接口需包含异常捕获，利用FastAPI的HTTPException返回清晰的错误信息（如“OCR识别失败：文件格式不支持”），便于开发调试和用户理解；

- 接口命名：采用RESTful风格，命名简洁明了，如“/api/document/upload”（文档上传）、“/api/model/add”（新增模型）；

- 接口文档：利用FastAPI自动生成接口文档（访问/docs路径），方便前端开发人员对接。

### 2.3 安全规范

- API KEY保护：模型配置中的API KEY、PaddleOCR的Token、Supabase的密钥需通过环境变量配置（Vercel环境变量），前端不直接暴露原始密钥，后端通过环境变量读取；

- 文件上传安全：FastAPI后端校验上传文件的格式、大小（限制单文件大小，避免过大文件导致系统卡顿），防止恶意文件上传；NEXT.js前端提前做格式校验，减少无效请求；

- 权限控制：利用Supabase的身份认证功能，实现简单权限区分（如普通用户仅可上传/查看自己的文档，管理员可管理所有文档和模型），可根据需求扩展；

- 跨域处理：FastAPI后端配置CORS，允许NEXT.js前端域名访问，确保前后端跨域交互正常。

### 2.4 UI开发规范（基于NEXT.js）

- 布局原则：简洁清晰、一致性、易用性、适配性，利用NEXT.js的布局组件（Layout）实现全局统一导航；

- 组件规范：按钮、输入框、弹窗、导航等组件统一风格，交互逻辑一致，可封装通用组件（如按钮、弹窗）提升开发效率；

- 视觉风格：简约、专业，浅色调底色，核心元素颜色鲜明不刺眼，字体清晰易读，结合Tailwind CSS实现响应式设计；

- 状态管理：使用React Context或Zustand管理全局状态（如当前选中文档、对话历史、模型配置），确保页面切换时状态保留。

### 2.5 部署规范（Vercel）

- 前端部署：NEXT.js项目直接关联Vercel仓库，配置环境变量（如后端接口地址、Supabase相关参数），开启自动部署；

- 后端部署：FastAPI项目通过Vercel的Serverless Functions部署，创建api目录存放后端代码，配置vercel.json文件指定运行环境和路由；

- 环境变量：所有敏感参数（Supabase密钥、PaddleOCR Token、LLM API KEY）均通过Vercel后台配置环境变量，避免硬编码；

- 部署校验：部署完成后，校验接口可正常访问、文件上传/OCR识别/问答功能正常，确保无跨域、接口调用失败等问题。

## 三、核心模块开发需求

### 3.1 OCR接口集成（PaddleOCR-VL 1.5）

#### 3.1.1 接口基础信息

| 参数 | 值 |

|------|----|

| API 地址（提交 Job） | `https://paddleocr.aistudio-app.com/api/v2/ocr/jobs` |

| API Token | `cf4a0b67edaf87887f0f5c1c81e4f5c89e9a4481` |

| 模型标识 | `PaddleOCR-VL-1.5` |

| 认证方式 | `Authorization: bearer <TOKEN>`（注意是小写 bearer） |

#### 3.1.2 调用流程（异步 Job 模式）

1. POST /api/v2/ocr/jobs  →  提交 OCR 任务，返回 jobId；

2. GET  /api/v2/ocr/jobs/{jobId}  →  轮询任务状态（pending/running/done/failed）；

3. GET  {jsonUrl}  →  下载 JSONL 格式的OCR识别结果；

4. 解析JSONL结果，提取Markdown格式文本或块级结构内容，存储到Supabase数据库，用于后续LLM问答。

#### 3.1.3 接口调用实现要求（基于FastAPI）

##### （1）请求方式支持

- 支持本地文件上传（核心方式）：用户在NEXT.js前端知识库管理页面上传本地Word/TXT/PDF（扫描件、电子版）、图片文件，FastAPI后端通过File依赖接收文件后，调用PaddleOCR接口提交OCR任务；

- 支持URL模式（可选）：若文件已在线上，前端输入文件URL，后端接收URL后，通过PaddleOCR接口提交OCR任务，满足特殊场景需求。

##### （2）参数配置

固定配置optionalPayload，关闭不必要的功能以提升识别速度：

{

"useDocOrientationClassify": False,  // 关闭方向纠正（加速）

"useDocUnwarping": False,            // 关闭扭曲纠正

"useChartRecognition": False,        // 关闭图表识别

}

##### （3）轮询与结果处理

- 轮询频率：每5秒轮询一次任务状态，避免频繁请求导致接口限流；

- 状态处理：

- pending/running：FastAPI后端返回“识别中”状态，NEXT.js前端显示“OCR识别中...”加载提示；

- done：后端下载JSONL结果，解析出Markdown文本（优先），存储到Supabase数据库，同时返回识别结果给前端，前端更新文档列表并展示OCR内容；

- failed：后端捕获错误信息，返回具体错误提示，前端显示“OCR识别失败：{错误信息}”，允许用户重新上传文件。

##### （4）结果解析要求

- 优先提取layoutParsingResults中的markdown.text（整页Markdown文本），用于文档内容展示和LLM读取；

- 可选提取prunedResult.parsing_res_list中的块级结构（block_label、block_content等），用于后续文档内容编辑（如精准修改某段文本）；

- 解析后的文本需保留原文档的段落结构，确保可读性和完整性。


#### 3.2.2 问答交互页面（核心页面）

##### 页面结构

1.  顶部导航：基于NEXT.js Layout组件实现，包含系统名称、3个页面导航入口（问答交互【高亮】、知识库管理、模型配置），使用Next/Link实现页面跳转，保持路由同步；

2.  对话区域（主体）：历史对话区（用户提问+系统回答）、当前输入区（输入框、提示词设置、清空上文、提问按钮）；

3.  加载提示：提问后、OCR识别中显示加载状态，使用React状态管理加载状态，避免用户重复操作。

##### 核心交互开发

- 接口请求：封装axios请求函数（lib/api.js），统一处理请求头、异常捕获，对接FastAPI后端接口；

- 输入框：支持换行，Enter键提交，输入为空时提问按钮禁用，使用React状态绑定输入内容；

- 提示词设置：点击按钮弹出抽屉/弹窗（使用Element Plus或自定义组件），分为系统提示词、用户提示词两个可编辑区域，支持保存/取消，保存后调用后端接口同步提示词；

- 清空上文：点击弹出确认弹窗，确认后调用后端清空接口，同时清除前端状态中的历史对话；

- 提问交互：点击提问按钮，前端提交问题到FastAPI后端，后端调用LLM模型（基于已上传文档的OCR内容），返回回答后更新前端历史对话状态，实现实时刷新。

#### 3.2.3 知识库管理页面

##### 页面结构

1.  顶部导航：与全局布局一致，当前页面高亮；

2.  文档操作区：上传文档按钮（使用Next/Upload组件）、可选搜索/筛选框；

3.  文档列表区（左侧）：展示文档名称、格式、上传时间、删除按钮，使用React列表渲染，绑定Supabase返回的文档数据；

4.  文档内容区（右侧）：展示选中文档的OCR识别文本（可编辑，使用textarea或富文本组件），无选中文档时显示提示。

##### 核心交互开发

- 上传文档：

1.  前端使用Next/Upload组件，限制文件格式（Word/TXT/PDF/图片），校验文件大小；

2.  上传文件到FastAPI后端，后端调用PaddleOCR接口进行识别，前端通过轮询或WebSocket获取识别状态；

3.  识别成功后，前端调用文档列表接口，更新文档列表，自动选中该文档并展示OCR内容；

4.  识别失败时，显示错误提示（通过全局提示组件），允许用户重新上传。

- 文档删除：点击删除按钮，弹出确认弹窗，确认后调用后端删除接口，前端同步删除列表条目，若该文档为当前选中状态，清空文档内容区。

- 文档编辑：文档内容区支持文本编辑，编辑后点击保存按钮，调用后端更新接口，同步更新Supabase数据库中的OCR内容，保存成功后显示提示。

#### 3.2.4 模型配置页面

##### 页面结构

1.  顶部导航：与其他页面一致，当前页面高亮；

2.  模型操作区：新建模型按钮；

3.  模型列表区：展示模型名称、URL、隐藏后的API KEY、编辑/删除按钮，渲染Supabase返回的模型配置数据；

4.  模型配置弹窗：新建/编辑模型时弹出，包含模型名称、URL、API KEY输入框，保存/取消按钮，使用表单组件实现参数输入和校验。

##### 核心交互开发

- 新建模型：使用表单组件校验输入参数（必填项、URL格式），提交到FastAPI后端，后端存储到Supabase模型表，前端更新模型列表；

- 编辑模型：点击编辑按钮，弹窗自动填充当前模型参数（从Supabase获取），修改后提交，后端更新数据库，前端同步刷新列表；

- 删除模型：点击删除按钮，弹出确认弹窗，确认后调用后端删除接口，前端删除列表条目；

- API KEY隐藏：前端展示时仅显示前4位和后4位（如“sk-xxxx****xxxx”），hover时通过弹窗显示完整内容（需确认），避免密钥泄露。



### 3.5 LLM模型调用开发（基于FastAPI）

#### 3.5.1 调用逻辑

1.  前端提交问题时，FastAPI后端通过Supabase接口获取用户选择的模型（或默认模型）的URL和API KEY（解密后）；

2.  若指定文档，通过Supabase接口读取该文档的OCR内容；

3.  拼接系统提示词、用户提示词和OCR内容，生成完整的prompt；

4.  调用OpenAI兼容模型的API，提交prompt，获取回答；

5.  将问题、回答、提示词、关联文档ID等信息存储到Supabase对话历史表，同时返回回答给前端。

#### 3.5.2 注意事项

- 模型API KEY加密存储：使用Supabase的加密函数或Python加密库对API KEY进行加密，调用时解密，避免泄露；

- 异常处理：处理模型调用异常（如接口超时、API KEY错误、上下文长度超限），通过HTTPException返回明确的错误提示；

- 上下文控制：因文档仅十几页，无需分段处理，直接拼接完整OCR内容，确保不超过模型的上下文限制；

- 环境变量配置：模型API KEY、模型URL等参数通过Vercel环境变量配置，便于后续修改和维护。


## 四、交互细节补充（前后端联动）

1.  页面切换：基于NEXT.js的路由跳转，切换页面时，通过React Context或Zustand保留当前页面状态（如对话历史、选中文档、选中模型），刷新页面后从Supabase接口获取状态，实现状态恢复；

2.  加载提示：所有异步操作（文件上传、OCR识别、LLM问答、接口请求），前端均显示加载提示（如按钮加载状态、页面加载动画），后端返回状态同步给前端，加载完成后自动隐藏；

3.  错误提示：后端通过FastAPI返回的HTTPException错误信息，前端统一通过全局提示组件（如Element Plus的Message组件）展示，告知用户具体原因和解决方法；

4.  数据同步：前端操作（如编辑文档、新增模型）后，立即调用后端接口同步数据，同步成功后更新前端状态，确保前后端数据一致；

5.  会话保持：利用Supabase的身份认证功能，用户登录后，会话信息存储在浏览器中，刷新页面后仍可保持登录状态，访问自己的文档和对话历史。

## 五、开发优先级

1.  环境搭建：搭建NEXT.js前端项目、FastAPI后端项目，配置Supabase客户端，完成基础环境部署；

2.  核心功能完整性：OCR接口集成（FastAPI+PaddleOCR-VL 1.5）、文档上传与识别、Supabase数据存储、LLM模型调用、基础问答功能；

3.  页面开发：优先开发知识库管理页面（文件上传+OCR）和问答交互页面，再开发模型配置页面；

4.  接口开发：配合前端页面开发，逐步实现文档管理、模型配置、问答交互相关接口，完善异常处理；

5.  细节优化：UI交互优化、加载提示、数据校验、权限控制；

6.  部署上线：完成Vercel前后端部署，进行功能校验和Bug修复。

## 六、备注

1.  本系统不采用RAG技术，无需设计文档切片、向量库相关功能，LLM直接读取OCR识别后的完整文档内容进行问答；

2.  文档仅支持十几页，无需设计分页查看功能，文档内容区支持滚动查看即可；

3.  PaddleOCR-VL 1.5接口需严格按照提供的基础信息和调用流程集成，确保Token、请求参数正确，Token通过Vercel环境变量配置；

4.  NEXT.js前端开发需确保适配常见电脑屏幕尺寸，利用Tailwind CSS实现响应式设计，避免元素溢出、显示不全；

5.  FastAPI后端开发需注重接口性能，尤其是OCR轮询和LLM调用，避免长时间阻塞，可使用异步函数优化；

6.  Supabase数据库参数（URL、密钥等）后续补充，补充后需同步更新前后端环境变量配置；

7.  Vercel部署时，需确保前后端环境变量配置正确，跨域设置合理，避免接口调用失败；
